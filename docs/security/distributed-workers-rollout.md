# Distributed worker coordination

Reconciliation (including the admin Run action), rate-quote cleanup (including CLI), subscription lapse, and dunning use dedicated PostgreSQL session advisory locks. Stable job IDs 1–4 use namespace 3; different jobs may run concurrently. Timers still wait for each run to finish. Scheduled and cron contention is skipped; manual reconciliation returns HTTP 409 `worker_busy`.

`DIRECT_URL` must point to the same database as `DATABASE_URL` using direct/session mode. Port 6543 and `pgbouncer=true` are rejected. Do not switch this connection to transaction pooling. Each active worker consumes an additional session. Session locks have no clock-based expiry; process/session termination releases them. The configured production session endpoint passed an isolated two-client probe proving exclusion and release after disconnect (no business jobs run).

A heartbeat checks ownership every five seconds, and Prisma queries and external dispatch boundaries (including carrier discovery, rate requests, and Supabase owner lookup) check before starting new work. Ownership failure aborts subsequent work; there is no unlocked fallback. An already dispatched database/provider operation may still finish after connection loss. This is not exactly-once execution or a replacement for provider idempotency. Live webhook deliveries do not take worker locks; existing handler idempotency still applies. A hung provider call retains its session lock until it returns or the process/session terminates.

Dunning uses a conditional snapshot update for expiration, with the brand mirror and audit in the same transaction, so a renewal after candidate selection is preserved. Payment-failed email remains best effort: its notification marker is claimed before delivery; failure/crash may drop a notice, and a renewal after claim may still receive the already-dispatched notice. Reliable delivery would require an outbox, outside this change.

Validation before deployment: 484 offline tests; 21 disposable PostgreSQL tests covering contention, failure/disconnect release, transaction/raw-query guards, shared production entry points, and dunning/lapse races. Workspace typecheck and build passed. No schema migration required. Never run destructive integration fixtures against production.

Rollback: redeploy the previous release (`ed18c6f`) if needed. That removes distributed coordination; only in-process exclusion remains. The database schema is unchanged.

Independent final review found three important issues, all reproduced and fixed: cron contention exit status; cluster-wide backend termination in the test fixture; and nested provider requests after ownership loss. No minor findings were deferred. The foreign-database test session survives the revised targeted termination fixture. Typecheck/build and all tests were rerun after the fixes.

Accepted decisions: dedicated session locks cost one connection per active job; this avoids timed-lease expiry during slow jobs. The adjacent dunning renewal fix preserves best-effort email, including possible dropped notices. In-flight operations cannot be fenced, so provider idempotency remains necessary. Live webhook idempotency remains separate. Guaranteed email delivery needs an outbox. Production session capacity must accommodate up to four concurrent worker sessions per instance (plus brief contenders); the configured endpoint passed the session probe, but future scaling requires capacity review.
